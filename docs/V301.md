# XSKT2 V3.0.1 — Stability & Historical Recovery

- Source table parser accepts ascending/descending labeled prize rows, padded/unpadded day labels, identical duplicate tables and nested regional tables. Conflicting tables, missing dates, bad prize lengths, source disagreement and current five-digit DB are rejected. Minh Ngoc fallback is the same publisher's all-region date URL; it does not count as another independent source. Each source is reported separately on failure. Actual live DOM not available in build environment; tests use synthetic HTML. A daily probe can verify the real page without writing data.
- Historical 5-digit DB can be evidence **only** if both configured publishers agree on all named full values, match the original non-DB full values, and DB matches exactly or original 5-digit DB is a suffix of verified 6-digit DB. No padding. The raw file remains immutable. Existing sidecars are not overwritten. Five-digit DB by itself never promotes historical data. The 94 other invalid-shaped dates remain quarantined for manual review. A source error is not proof of no draw or bad historical data.
- Recovery batches capped at 10; prior unresolved dates eligible once per parser version (maximum 3 recorded attempts total). Same-version failed dates are skipped. Historic source may have no southern archive: successful workflow does not guarantee recovery. Old unresolved audit retained unless retried, with attempts and checkedAt updated; no scheduled recovery by default.
- `scripts/probe_v301.py --date YYYY-MM-DD` fetches both sources for a completed draw, compares with existing validated raw if present, writes nothing. `V3.0.1 Stability Checks` Actions has a manual probe plus read-only deployment check. Scheduled check compares live bytes for package, SW, dashboard JS, health and report with the checked-out main; revision must match. It does not change Pages settings or deploy. A mismatch may be due to deployment propagation or concurrent commit; rerun after Pages completes. Source probe may still fail if live site DOM differs or data not archived.
- PWA cache version 3.0.1; no changes to Universal, Personal, prediction calendars, statistical formulas, or raw records. Rebuild/report still through existing Update XSMN History workflow.
