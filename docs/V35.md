# XSKT2 V3.5 — Guide scenario arithmetic

Supports V3.3.0 and V3.4.0. The V3.3 path stages the bundled V3.4 edits, then the V3.5 changes, validating all anchors before writing. Do not apply on a dirty working tree. From repo: `python3 ~/Downloads/xskt2-v35-patch/apply_patch.py --check`, then without `--check`. Run `npm test` and `bash scripts/check_web.sh`; inspect changes before committing. No history, scoring, workflow or prediction core changes.

- Direct Top 1 / Top 2 buttons, selected count, cost per number, cost for the whole first day, gross per hit and net for the first day. Both monetary fields remain synced.
- Displays separate fixed-cost and conditional legacy mathematical scenarios for each selected date. The latter assumes all earlier dates MISS and uses base-amount multiples from XSKT guide v4.5. Not a betting recommendation. For Top 2 at 75,000 VND per number, 4-day theoretical total if all MISS is 1,050,000 VND, versus 600,000 fixed. Losses may be large, and no predictive advantage is established.
- Actual historical outcomes and number of hits are separate from scenarios. Review stops at first WIN, missing result, budget or end. After stop, later actual results are still visible but never counted as money spent. A fixed-stake WIN can still leave a loss.
- Zero budget means no personal cap set, mathematical preview only; the hard display cap is 1 billion VND, not a suggested budget. A positive user cap limits scenarios. Amounts are floored to 15,000 VND steps, minimum one.
- Strict monthly selection retained, first station by schedule, versioned imports and service worker. No production test or remote write performed. New unit tests exercise arithmetic using a local fixture; run full repository and deploy checks locally.
