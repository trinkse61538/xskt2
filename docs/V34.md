# XSKT2 V3.4 — versioned monthly review

Requires V3.3.0. From the repository: `python3 ~/Downloads/xskt2-v34-patch/apply_patch.py --check`, then run without `--check`, `npm test`, and `bash scripts/check_web.sh`. Inspect changes before committing. No data, scoring or history workflows are changed.

- Both screens retain V3.2's month-only selection. November never spills into December, even when the requested sample exceeds remaining days.
- Guide offers Top 1 (only primary) / Top 2 (primary and secondary), default Top 2, and matches observed results against the selected numbers on the first scheduled station. Cost simulation uses the user-entered fixed amount and count of numbers, not a suggested stake. Historical comparison of the old formula remains Top 2 only. No future loss-chasing schedule is added.
- Both input fields remain synchronized via V3.3 handlers. All day rows show WIN/MISS/pending/missing/load failure independently of the simulation budget.
- Versioned entry point, screen and changed guide/monthly module URLs, new service worker cache name, precached versioned module URLs, and reload on controller change reduce stale shell/module mixing. Existing open iPhone app may still require one manual close and reload. This cannot correct a failed Pages deployment.
- For deployment verification after pushing and successful Pages build: `python3 scripts/check_deployment_v301.py`. If the verifier reports a data revision changed during deploy, pull current main and retry; if it reports static files differ, investigate Pages before clearing iPhone data. Do not clear website data unnecessarily (local personal profile may be lost).
- Acceptance case, Universal, November 2026, start Nov 1, 4 selected days, Top 2: Nov 16, 17, 19, 23; 1 WIN, 3 MISS per repository report through Nov 25. No December days. Selecting Top 1 changes result scope but not selected dates. Historical records are not forecasts.

Test limitations: new tests exercise local modules using a small synthetic fixture and a mocked data-loading boundary; full repository test suite and actual iPhone browser need to be run by the user. No GitHub push performed.
