# XSKT2 V3.0 — Unified Research & Integrity

Frozen Universal V1.0 and existing calendar artifacts unchanged. Personal V1.1 remains local. The app compares retrospective Universal/V5.1/random and separately evaluates Personal on the device; it does not certify predictive power. No change to guidance or ranking engine.

## Historical integrity
- Raw JSON is immutable. Strict current validation is preserved. Historical records with five-digit special prizes are audited separately, never accepted automatically. The historical shape check validates the stored values and tails directly; no padding is performed.
- Optional verification (0–10 dates per Actions dispatch) checks both named-station sources, xoso.com.vn and minhngoc.net.vn, for exact full-value agreement and matching legacy prize tails. A successful match creates an evidence sidecar tied to raw SHA-256; existing raw stays unchanged. Sidecars contain source URL/hash and corrected values, not full archived HTML, and are not independent cryptographic attestations. No blanket recovery of the 1,295 dates is claimed. Review source terms, use low request rate, and do not retry indefinitely.
- Recent crawler requires both sources to agree. Source HTML adapters fail closed on ambiguity, date mismatch, layout change, source disagreement or unavailable source; this can delay updates. Tests use synthetic HTML; actual live HTML DOM needs a first live workflow run. If a date fails, diagnostics are kept; no invented records.
- Health covers all years from 2005, even entirely missing years. Old unresolved records do not independently fail the daily workflow; new rejected records or incomplete fetch do. Legacy NO_DRAW remains unverified. Existing valid-shaped historical data is not equivalent to independently verified data.

## Research
- Automated backtest with the V5.1 reference pinned at commit `2accbacde384b5e514d4f5dcda8f0f07e5cc767b`; scope and N visible. V5.1 comparison only on overlapping published dates. CI/p-values descriptive, unadjusted for temporal dependence; holdout date split not proof of untouched data.
- Rolling 90 recorded draw days, coverage by year, paired two-sided test on discordant days, model comparison and locally evaluated Personal (30/90/365 calendar days). No profile upload.
- Ledger report checks runner timestamp and calendar SHA-256; not independent timestamp proof. Newly published daily ledger must accumulate prospectively. Research report revision must match data revision.
- PWA cache v3 and JS + Python CI. Existing offline behavior is cache-based, not full offline corpus. No paid APIs.
